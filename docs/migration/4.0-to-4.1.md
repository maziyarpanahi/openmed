# Migrating from OpenMed 4.0 to 4.1

OpenMed `4.1.0` is not published yet. This guide collects each change that
needs a migration note as it lands. The
[changelog](https://github.com/maziyarpanahi/openmed/blob/master/CHANGELOG.md#unreleased)
lists every change since 4.0.

## OpenMedKit for Android

OpenMedKit Android commits its public API baseline at
`android/openmedkit/api/openmedkit.api`. The changes below alter a recorded
declaration without breaking callers. They are source-compatible for Kotlin
and binary-compatible: apps and libraries compiled against 4.0 keep linking
without a rebuild.

### Model catalog family, task and labels

`ModelCatalogEntry` gains `family`, `task` and `canonicalLabels`, read from the
bundled catalog, and `ModelCatalog.filter` can select a model family. See
[List available models](../android-integration.md#list-available-models).

| Symbol | Change | Migration |
| --- | --- | --- |
| `com.openmed.openmedkit.catalog.ModelCatalog.filter` | Adds a trailing `family: String? = null`. The 4.0 five-argument `filter` stays as a hidden bridge for compiled callers | None for Kotlin. Java sources pass `null` for `family` |
| `com.openmed.openmedkit.catalog.ModelCatalogEntry.copy` | Adds `family`, `task` and `canonicalLabels`, all defaulted. The 4.0 seven-argument `copy` stays as a hidden bridge that keeps the new fields | None for Kotlin. Java sources pass the entry's `getFamily()`, `getTask()` and `getCanonicalLabels()` |

The seven-argument `ModelCatalogEntry` constructor is unchanged and leaves the
new fields empty. A catalog asset built before 4.1 still loads, with `family`
and `task` null and `canonicalLabels` empty.
